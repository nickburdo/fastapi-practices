# План: автоформатирование кода Ruff при сохранении

**Статус:** выполнен (2026-11-01). Утверждён 2026-11-01, включая предложения F6–F9 (F10 отменено в R5).
Проверка этапа 5 пройдена: форматирование и сортировка импортов при сохранении работают,
неиспользуемые импорты не удаляются.
**Исполнитель реализации:** пользователь
**Окружение:** PyCharm 2025.3+, Python 3.15.1 (`.venv`), Ruff 0.17.3 (последняя версия на 2026-11-01)

## Цель

При сохранении `.py`-файла в PyCharm код автоматически приводится к стилю PEP 8
(отступы, пробелы, пустые строки, переносы) и сортируются импорты.
Те же правила доступны из терминала — конфигурация лежит в проекте, а не только в IDE.

## Вне рамок

- Массовое форматирование существующих файлов — файлы форматируются постепенно, по мере сохранения.
- Автоудаление неиспользуемых импортов и другие автоисправления линтера.
- pre-commit, CI, файл зависимостей (`requirements.txt` / `[project]` в `pyproject.toml`) — в проекте их пока нет.

## Порядок относительно плана `refactor-books-plan.md`

Рефакторинг ставится на паузу после этапа 5. Сначала выполняется этот план,
затем этапы 6–9 рефакторинга — уже с работающим форматированием при сохранении.
Шаги рефакторинга про «две пустые строки» (6.5, 7.6, 8.6) после этого выполнятся сами при сохранении.

> F2: Ruff-форматтер сам импорты не сортирует — по документации Ruff для этого нужен линтер с правилом `I`

## Этап 1. Установка Ruff в `.venv`

Команды выполняются в терминале PyCharm, открытом в корне проекта, с активированным `.venv`.

**1.1.** Установить Ruff фиксированной версии (F6):

```
pip install ruff==0.17.3
```

**1.2.** Проверить установку:

```
ruff --version
```

Ожидаемый вывод:

```
ruff 0.17.3
```

## Этап 2. Конфигурация (`pyproject.toml`)

**2.1.** Создать в корне проекта файл `pyproject.toml`:

```toml
[tool.ruff]
line-length = 88
extend-exclude = ["docs"]

[tool.ruff.lint]
extend-select = ["I"]
unfixable = ["F401"]
```

Что значит каждая строка:

- `line-length = 88` — максимальная длина строки (F3);
- `extend-exclude = ["docs"]` — Ruff не трогает `docs/` (F11, добавлено в R6);
- `extend-select = ["I"]` — к правилам по умолчанию добавляется сортировка импортов (isort);
- `unfixable = ["F401"]` — неиспользуемые импорты Ruff только подсвечивает, но никогда не удаляет автоматически (F2).

Папку `.venv` Ruff по умолчанию не проверяет — исключать её отдельно не нужно.

**2.2.** Проверить конфигурацию из терминала — команды **ничего не меняют**, только показывают:

```
ruff format --check .
ruff check --select I .
```

Первая печатает файлы, которые Ruff переформатировал бы; вторая — файлы с несортированными импортами.
Ошибки вида `Would reformat: ...` и `I001` здесь ожидаемы (F4) — это не сбой.
Сбой — только ошибка разбора `pyproject.toml`.

## Этап 3. Ruff в PyCharm

> Этап сверен со скриншотом страницы в PyCharm пользователя (2026-11-01).
> Страница — таблица со столбцами **Tool**, **Lookup**, **Executable Path**.

**3.1.** Открыть Settings (`Ctrl+Alt+S`) → **Python → Tools → External Tools**.

**3.2.** В строке **Ruff** переключатель — в положении **ON**.

**3.3.** Столбец **Lookup** у Ruff (F7): у **Sdk** стоит зелёная галочка ✓ —
PyCharm нашёл Ruff в интерпретаторе проекта (`.venv`), установленный на этапе 1.
Интерпретатор проекта должен быть `.venv` (Settings → Python → Interpreter).

**3.4.** Столбец **Executable Path** — `Not found in $PATH` это **нормально**:
столбец показывает только поиск в системном `PATH`, а Ruff берётся из `.venv` через Sdk.
Ничего не менять.

**3.5.** Функции Ruff показаны в квадратных скобках рядом с именем:
`[Inspections, Formatting, I…]`. Убедиться, что в списке три функции (F8):

- **Inspections** — подсветка замечаний;
- **Formatting** — Ruff вместо встроенного форматтера PyCharm;
- **Import optimizer** — Ruff сортирует импорты (в таблице название обрезано до `I…`).

Полный список открывается кликом по значку-шестерёнке ⚙, который появляется
при наведении курсора на список функций в строке Ruff.

**3.6.** Apply.

## Этап 4. Действия при сохранении

**4.1.** Settings → **Tools → Actions on Save**.

**4.2.** Отметить **Reformat code**. Выпадающий список **All file types** не менять.

Больше ничего не настраивать:

- ссылка **Configure scope...** (появляется при наведении) открывает Editor → Code Style → Formatter
  с полем **Do not format** — это исключения из форматирования; оставить пустым;
- выбора «весь файл / только изменённые строки» в интерфейсе нет: проект не под git,
  поэтому PyCharm всегда форматирует файл целиком — F9 выполняется без настройки.

**4.3.** Отметить **Optimize imports**. При включённом Ruff Import optimizer (шаг 3.4)
сортировку выполняет Ruff; результат проверяется на шаге 5.4.

**4.4.** Apply.

## Этап 5. Проверка

**5.1.** Создать в корне проекта временный файл `ruff_check_tmp.py` с намеренно плохим стилем:

```python
from sqlalchemy import String
import os
from pathlib import Path
import json
x=1
def f( a,b ):
    return a+b
class A:
    pass
```

**5.2.** Сохранить файл (`Ctrl+S`).

**5.3.** Ожидаемый результат — импорты отсортированы и сгруппированы
(стандартная библиотека → сторонние пакеты), пробелы и пустые строки по PEP 8:

```python
import json
import os
from pathlib import Path

from sqlalchemy import String

x = 1


def f(a, b):
    return a + b


class A:
    pass
```

**5.4.** Проверить, что **ни один импорт не удалён**: все четыре (`json`, `os`, `Path`, `String`) не используются,
но остались в файле и только подсвечены как неиспользуемые (F2, F8).

**5.5.** Удалить `ruff_check_tmp.py`.

**Если на 5.4 импорты удалились** — сортировку выполнил встроенный Optimize Imports PyCharm, а не Ruff.
Остановиться и вернуться к обсуждению плана, ничего не меняя самостоятельно.

## Приложение. Форматирование всех файлов проекта (по желанию)

Не входит в обязательные шаги (F4 — файлы форматируются при сохранении).
Используется, когда нужно разом привести все `.py`-файлы проекта к правилам из `pyproject.toml` —
тот же результат, что даёт сохранение каждого файла в PyCharm.

Запускать в терминале в **корне проекта** с активированным `.venv`.
Без аргументов Ruff обрабатывает текущую папку и всё внутри неё;
`.venv` и `docs/` исключены (F11), неиспользуемые импорты не удаляются (F2).

**П.1.** Посмотреть, какие файлы изменятся — команды **ничего не меняют**:

```
ruff check --select I
ruff format --check
```

**П.2.** Отсортировать импорты:

```
ruff check --select I --fix
```

**П.3.** Отформатировать код:

```
ruff format
```

Порядок важен: сначала импорты, потом форматирование — Ruff-форматтер сам импорты не сортирует.

**П.4.** Проверить, что всё приведено к правилам — обе команды не должны ничего найти:

```
ruff check --select I
ruff format --check
```

Ожидаемый вывод:

```
All checks passed!
N files already formatted
```
