## Этап 1. Зависимости (`pyproject.toml`) — ВЫПОЛНЕН в плане `uv-migration-plan.md`, не выполнять

> Оставлен для истории. Зависимости уже записаны через uv (`[project].dependencies`, группа `dev`, `uv.lock`).

> **Проблема.** Пакеты, нужные проекту (FastAPI, SQLAlchemy и др.), есть только в `.venv`,
> но нигде не записано, какие именно и каких версий. Удалили `.venv`, перешли на другой компьютер,
> передали проект коллеге — придётся угадывать; новые версии могут работать иначе.
>
> **Что делаем.** Записываем в `pyproject.toml` список пакетов с точными версиями, которые сейчас работают.
> Две группы: `app` — без чего не запустится сервер; `dev` — инструменты разработчика (Ruff).
>
> **Результат.** Окружение собирается одной командой и получается точно таким же, как сейчас.

**1.1.** Добавить в **начало** `pyproject.toml` (перед `[tool.ruff]`) группы зависимостей:

```toml
[dependency-groups]
app = [
    "aiosqlite==0.22.1",
    "fastapi[standard]==0.162.0",
    "pydantic-settings==2.16.2",
    "sqlalchemy[asyncio]==2.1.6",
]
dev = [
    "ruff==0.17.3",
]
```

Секции `[tool.ruff]` и `[tool.ruff.lint]` не менять.

**1.2.** Проверить установку из терминала (корень проекта, активированный `.venv`).

## Этап 3. Порядок списка книг (`books/repositories.py`)

> **Проблема.** `GET /books/` просит у базы «все книги», но не говорит, в каком порядке.
> SQLite обычно отдаёт по порядку добавления, но не обязан; другая БД (PostgreSQL) может
> менять порядок от запроса к запросу.
>
> **Что делаем.** Явно сортируем по `id` — книги всегда идут в порядке создания.

**3.1.** В `get_all_books` добавить сортировку по `id`:

```python
    query = select(BookModel).order_by(BookModel.id)
```

## Этап 4. Схемы (`books/schemas.py`)

> **Проблема.** Ограничение «название от 1 до 255 символов» сейчас проверяется дважды:
> когда клиент присылает книгу (правильно) и когда сервер отдаёт книги из базы (лишнее).
> SQLite длину не ограничивает. Если в базу как-то попадёт книга с пустым или слишком длинным
> названием (вставили вручную, импорт, старые данные), то `GET /books/` целиком упадёт с `500` —
> сломается весь список, а не одна запись. Проверено на временной базе.
>
> **Что делаем.** Ограничения длины проверяем только на входе:
>
> - `BookBaseSchema` — общие поля `title`, `author`, без ограничений;
> - `BookCreateSchema` — что присылает клиент: те же поля, но с ограничениями;
> - `BookSchema` — что отдаёт сервер: поля + `id`, без ограничений.

**4.1.** Добавить базовую схему **без** ограничений — перед `BookCreateSchema`:

```python
class BookBaseSchema(BaseModel):
    title: str
    author: str
```

**4.2.** `BookCreateSchema` наследовать от `BookBaseSchema`; поля с ограничениями остаются как есть:

```python
class BookCreateSchema(BookBaseSchema):
    title: str = Field(min_length=1, max_length=255)
    author: str = Field(min_length=1, max_length=255)
```

**4.3.** `BookSchema` наследовать от `BookBaseSchema` (а не от `BookCreateSchema`):

```python
class BookSchema(BookBaseSchema):
    id: int

    model_config = ConfigDict(from_attributes=True)
```

Импорты файла не меняются.

## Этап 5. Аннотации возврата эндпоинтов (`books/routes.py`)

> **Проблема.** У функций сервиса и репозитория указано, что они возвращают (`-> BookModel`),
> у функций в `routes.py` — нет. Это единообразие кода: без аннотаций PyCharm хуже подсказывает
> и не ловит ошибки типов.
>
> **Что делаем.** Дописываем типы возврата. На поведение API это не влияет —
> формат ответа по-прежнему задаёт `response_model`.

**5.1.** Добавить импорты (Ruff при сохранении расставит их по группам):

```python
from collections.abc import Sequence

from books.models import BookModel
```

**5.2.** `read_books` — аннотация возврата:

```python
async def read_books(session: SessionDep) -> Sequence[BookModel]:
```

**5.3.** `create_book` — аннотация возврата:

```python
async def create_book(data: BookCreateSchema, session: SessionDep) -> BookModel:
```

`response_model` в декораторах **не убирать** — он задаёт схему ответа (C10).
