Зависимости проекта записываются в `pyproject.toml` автоматически (`uv add` — как `npm install`),
а точные версии всех пакетов, включая вложенные, фиксируются в `uv.lock` (как `package-lock.json`).

## Этап 1. Раздел `[project]` в `pyproject.toml`

> **Проблема.** uv хранит зависимости в разделе `[project]`, а у нас его нет.
> Команда `uv init`, которая обычно его создаёт, отказывается работать, если `pyproject.toml` уже существует.
>
> **Что делаем.** Добавляем раздел вручную — с пустым списком зависимостей; заполнит его uv.

**1.1.** Добавить в **начало** `pyproject.toml` (перед `[tool.ruff]`):

```toml
[project]
name = "fastapi-as"
version = "0.1.0"
requires-python = ">=3.15"
dependencies = []

```

Секции `[tool.ruff]` и `[tool.ruff.lint]` не менять.

## Этап 2. Зависимости приложения

> **Что делаем.** Одна команда: записывает 4 пакета в `[project].dependencies`, создаёт `uv.lock`
> с точными версиями всех 65 пакетов и приводит `.venv` в соответствие.
>
> **Чего ожидать.** Ничего не удаляется; обновляются 2 вложенных пакета (U5).

> **Перед командой остановить сервер** и всё, что запускает Python из `.venv`
> (Python Console, отладчик PyCharm). Windows не даёт заменять файлы пакетов, которые сейчас
> используются, — uv упадёт с `Access is denied. (os error 5)`. Это касается любых `uv add` / `uv remove` / `uv sync`.
>
> **Если ошибка всё же случилась** (R2): остановить сервер, затем `uv sync --dry-run`.
> Если он снова и снова предлагает удалить старую версию пакета (например, `- websockets==17.3`) —
> от неудачной попытки осталась пустая папка `.venv/Lib/site-packages/<пакет>-<версия>.dist-info`
> без файлов; uv не может её удалить сам. Убедиться, что в ней нет файлов, удалить её и повторить проверку:
>
> ```
> find .venv/Lib/site-packages/websockets-17.3.dist-info -type f
> rm -r .venv/Lib/site-packages/websockets-17.3.dist-info
> uv sync --dry-run
> ```

**2.1.** В терминале в корне проекта:

## Этап 3. Инструменты разработки

> **Что делаем.** Ruff нужен только разработчику, не серверу — uv кладёт его в отдельную группу `dev`
> (раздел `[dependency-groups]`). Группа `dev` ставится по умолчанию при `uv sync`.

**3.1.**

```
uv add --dev "ruff>=0.17.3"
```

## Этап 4. Проверка

**4.1.** `pyproject.toml` — uv дописал зависимости и группу `dev`:

```toml
[project]
name = "fastapi-as"
version = "0.1.0"
requires-python = ">=3.15"
dependencies = [
    "aiosqlite>=0.22.1",
    "fastapi[standard]>=0.162.0",
    "pydantic-settings>=2.16.2",
    "sqlalchemy[asyncio]>=2.1.6",
]

[tool.ruff]
line-length = 88
extend-exclude = ["docs"]

[tool.ruff.lint]
extend-select = ["I"]
unfixable = ["F401"]

[dependency-groups]
dev = [
    "ruff>=0.17.3",
]
```

**4.2.** В корне проекта появился файл `uv.lock`. Вручную его **не редактировать** — его ведёт uv.

**4.3.** Окружение совпадает с `uv.lock` — команда ничего не меняет, только показывает:

```

```

Ожидаемо: нет строк `Would install` / `Would uninstall`.

**4.4.** Ruff работает (форматирование при сохранении в PyCharm — тоже):

```

```

**4.5.** Сервер стартует, `GET /books/` в `/docs` → `200`.

## Этап 5. Новые привычки (шпаргалка)

> **Перед `uv add` / `uv remove` / `uv sync` — остановить сервер** (см. предупреждение в этапе 2).
>
> **Главное.** Пакеты больше **не ставятся через `pip install`**: pip не записывает их в `pyproject.toml`,
> и при следующем `uv sync` uv удалит всё, чего нет в `uv.lock`.

| Задача | Было (pip) | Стало (uv) |
|---|---|---|
| Добавить пакет | `pip install X` + дописать вручную | `uv add X` |
| Добавить инструмент разработки | `pip install X` + дописать вручную | `uv add --dev X` |
| Удалить пакет | `pip uninstall X` + удалить вручную | `uv remove X` |
| Собрать окружение (новый компьютер, после удаления `.venv`) | — | `uv sync` |
| Обновить пакеты до новых версий | — | `uv lock --upgrade`, затем `uv sync` |
| Запустить сервер / Ruff | в активированном `.venv` | так же; или без активации: `uv run python main.py`, `uv run ruff check` |
