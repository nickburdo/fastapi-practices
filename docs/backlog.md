## Пользователи и аутентификация

Источник: код-ревью ветки `feature/auth-jwt` (план `docs/plans/users-auth-plan.md`), 2026-11-02. Для учебного
проекта на SQLite ни один пункт не критичен; все становятся важными при реальной нагрузке или выкладке.

| # | Проблема | Где | Чем грозит | Возможное решение |
|---|---|---|---|---|
| B1 | Гонка при регистрации: два одновременных запроса с одним `username` оба проходят проверку «имя свободно» | `users/services.py` → `register_user` | Второй запрос падает на уникальном индексе: `500` вместо `409 "Username already taken"`. Уже записано в «Вне рамок» плана | Ловить `sqlalchemy.exc.IntegrityError` при `flush`/`commit` и превращать в `UsernameTakenError` |
| B2 | Argon2 синхронный и тяжёлый (64 МБ памяти, 3 прохода), а вызывается прямо внутри `async def` | `users/security.py`, вызовы из `users/services.py` | Каждый вход/регистрация блокирует event loop на ~50–100 мс; пачка запросов на вход (в том числе с несуществующими именами — проверка `DUMMY_HASH`) тормозит все остальные роуты | Выполнять хэширование и проверку в пуле потоков: `fastapi.concurrency.run_in_threadpool` или `anyio.to_thread.run_sync` |
| B3 | У пароля нет `max_length` | `users/schemas.py` → `UserCredentialsSchema.password` | Без входа можно отправить пароль в несколько МБ; вместе с B2 — дешёвый способ нагрузить CPU и весь API | `Field(min_length=1, max_length=128)` (или другой разумный предел) |
| B4 | Миграция всегда создаёт админа `admin` / `admin`, пароль известен из README | `migrations/versions/27139778c693_create_users_table.py` | В любой среде после `alembic upgrade head` есть админ с публичным паролем, который может удалять пользователей. Для учебного проекта выбрано сознательно (решение A3 плана) | Создавать админа отдельной CLI-командой с паролем из `.env`/ввода, а не в миграции; или требовать смену пароля при первом входе |
| B5 | Имена пользователей не нормализуются: нет обрезки пробелов и приведения регистра; уникальность в SQLite регистрозависима | `users/schemas.py` → `UserCredentialsSchema.username` | Можно зарегистрировать `Admin`, `admin ` и т. п. рядом с `admin` — похожие имена путают при выборе `user_id` для удаления | Продуктовое решение: `str_strip_whitespace=True` и/или хранить имя в нижнем регистре (или регистронезависимый уникальный индекс) |

Другие отложенные вещи из того же плана (logout, смена пароля, `GET /users/{user_id}`, refresh-токены, CORS,
назначение админа через API, тесты) перечислены в его разделе «Вне рамок».

| # | Проблема | Где | Чем грозит | Возможное решение |
|---|---|---|---|---|
| B6 | При удалении пользователя его файлы остаются: внешние ключи в SQLite не включены, `files.owner_id` указывает на удалённого пользователя | `users/services.py` → удаление пользователя; `files/models.py` | Записи и файлы на диске копятся; видит и может удалить их только админ.
